# Tusk

A lightweight PostgreSQL and SQLite browser and editor for macOS, released under the MIT license.

## Features

- Browse schemas, tables, views, and row previews.
- Write SQL with syntax highlighting, schema-aware completion, query tabs, and cancellation.
- Edit cells and remove rows in tables and eligible query results, with staged changes and conflict checks.
- Inspect and copy exact values, sort results, and export selected rows as CSV.
- Save connections with credentials encrypted using a key stored in macOS Keychain.
- Open existing SQLite files or connect to PostgreSQL using connection fields or a URL.

Tusk is in early development. macOS is the supported platform; build from source using the steps below. Signed, notarized release downloads are not available yet.

Built with Wails 3, Svelte 5, TypeScript, and CodeMirror 6, using pgx for PostgreSQL and go-sqlite3 for SQLite.

## Build from source

Requires macOS 13+, Xcode Command Line Tools, Go 1.26+, Node.js 22.12+ (or 24+), and Wails CLI **3.0.0**. Dependencies are pinned in `go.mod` and `frontend/package-lock.json`.

```sh
git clone https://github.com/Viedin/tusk.git
cd tusk
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0
cd frontend
npm ci
cd ..
wails3 dev
```

`wails3 dev` generates TypeScript bindings, builds the native app, starts Vite, and launches Tusk with hot reload. Opening Vite in a regular browser does not provide a database backend. Use the native app for normal development, or the Wails server test mode below for browser checks.

```sh
wails3 build          # native binary: bin/tusk
wails3 package        # app bundle: bin/Tusk.app
open bin/Tusk.app
```

The package is ad-hoc signed for local use. Developer ID signing and notarization for distribution are not configured.

If Xcode and Command Line Tools use different SDK versions and linking fails, select the matching SDK before building or running Go tests:

```sh
export SDKROOT="$(xcrun --sdk macosx --show-sdk-path)"
```

## Code layout

- `main.go` embeds the frontend and wires the Wails app, services, and shutdown.
- `internal/db` defines the shared `Provider` and `Store` interfaces, connection/catalog/result models, and result limits.
- `internal/database` owns the active session, operation gate, cancellation, timeouts, and Wails API. Providers are registered in `main.go`; a failed connection attempt keeps the current session open.
- `internal/postgres` and `internal/sqlite` implement provider-specific connection validation, catalog queries, and SQL execution.
- `internal/store` owns saved connections, SQLite storage, credential encryption, and platform-specific Keychain access.
- `internal/csvexport` opens the native CSV save dialog and writes exports atomically.
- `frontend/src` contains the Svelte UI; `frontend/bindings` is generated by Wails from the internal services.

Backend tests live alongside the packages they exercise. Run `wails3 generate bindings -ts -i -clean=true` after changing service packages or methods, then rebuild the frontend.

## Using Tusk

Choose **Database type → SQLite** to open a local database. Enter the absolute path to an existing SQLite file, then **Connect**. Name it to save it for later; saved SQLite connections support the same edit, switch, and confirmed-delete actions. SQLite connections open read/write without creating a missing file. Tables and views appear under `main`, with attached databases and temporary objects available after refreshing the sidebar. The SQL editor uses SQLite syntax and schema completion for these sessions. PostgreSQL connections retain the fields and URL methods below.

1. Tusk starts in a persistent app frame: saved databases in the sidebar and a new connection editor in the workspace. Switching between connection details and URL keeps the name, method switcher, and bottom action area in place; the form scrolls independently in smaller windows. In **Connection details**, enter the host, port, database, username, and password, then click **Connect**. Defaults are `localhost`, port `5432`, and database `postgres`; enter your own PostgreSQL username and password. Choose **Connection URL** to paste a `postgres://`, `postgresql://`, or PostgreSQL JDBC connection URL instead. Fields handle special characters in credentials automatically; percent-encode them when entering a URL. For a temporary session, leave **Connection name** blank and click **Connect**. To keep the connection, enter a name; the primary action becomes **Save & connect**. The database workspace opens after a successful connection. **Disconnect** returns to the connection view. Passwords and URLs are cleared from the form after a successful connection or encrypted save.
2. Choose a schema/table in the sidebar to load its first 100 rows. The shared workspace toolbar shows **Refresh rows** in the table browser and **Run query** in SQL; the active database and table tree stay in the sidebar. Click a column heading to sort ascending/descending across the full table before the preview limit; NULLs remain last. Sidebar search opens matching schemas while preserving your collapsed groups when the search is cleared. Refresh the sidebar after changing tables/columns with SQL.
3. Open **SQL**, enter one statement, and click **Run query** on the right side of the workspace toolbar. **Cmd+Enter** runs the selected SQL, or the whole editor when nothing is selected. Use **＋** beside the query tabs to open another query. Query numbers follow the open tabs’ order and update when a tab closes. Switching tabs preserves each query’s SQL, undo history, results, sorting, and staged row removals; Left/Right, Home, and End switch tabs when a tab has keyboard focus. Queries run one at a time, and you can switch tabs while one runs. Closing a tab with SQL asks before discarding it; save or undo staged removals before closing. Open tabs, their SQL text and order, and the selected tab are saved as you edit and restored after reopening Tusk and reconnecting. Run a restored query when you want fresh results. Schema-aware suggestions include tables, columns, and SQL keywords; use **Ctrl+Space** to request suggestions. In a simple query such as `SELECT * FROM "Assets" ORDER BY Id`, column suggestions infer the `FROM` table and insert the correctly quoted `"Id"`; joins use qualified column suggestions to avoid ambiguity. Metadata refreshes when connecting or refreshing the sidebar. Completion is intentionally basic: CodeMirror currently limits column-context suggestions after identifiers containing escaped double quotes; insertion and SQL execution still quote those names correctly. CTE and subquery column inference is not implemented.
4. Use **Cancel** to stop active database work. Use the visible horizontal scrollbar at the bottom of the result grid to reach every column. You can also focus the grid and use the arrow keys. Select a row number to show its actions, then choose **Copy row as CSV** to copy its values without headings or the row number. Right-click, **Shift+F10**, and the Menu key also open the same popup. Values containing commas, quotes, or line breaks are quoted; NULL uses an empty field and an empty string uses `""`. Select a result cell to inspect its full value in an overlay that keeps the grid columns in place. Press **Cmd+C** (or **Ctrl+C**) to copy the selected cell’s full value directly; selecting text in the inspector copies only that text. Empty strings copy as empty text, and SQL NULL copies as `NULL`. Press **Escape** to close the inspector. Long text and JSON wrap in the detail panel without adding line breaks to copied values.
5. Click a saved connection in the connection view, or open **Switch connection** in the workspace sidebar, to reconnect without entering its password. Saving happens before connecting, so a connection that fails authentication stays available for retry or deletion. Use the trash button, then **Delete**, to remove a saved entry; this does not disconnect an active session. Click the pencil on a saved entry to edit its name, color, or settings. A blank URL keeps the saved URL; passwords stay unchanged unless **Replace saved password** is selected (an empty replacement removes the password). **Save changes** updates the same entry without connecting or interrupting the active session. Connection setting changes take effect on the next connection. Saved lists with more than five entries include search; colored accents identify entries and the active connection. Quit to close the PostgreSQL connection and local SQLite database.

SQL runs with the connected account's or local file's permissions and **can change data**. Each execution accepts one statement, including a SQLite trigger definition with its internal statements. Writes use the database's autocommit behavior; explicit transaction workflows and multi-statement scripts are out of scope.

Click or drag the **#** row numbers to select rows. **Shift-click** or **Shift+Up/Down** extends a range; **Cmd-click** toggles individual rows, and the **#** heading selects all displayed rows. **Export → CSV with headers** saves the selection in displayed order, including column names. Export covers the loaded preview or query result, including staged cell values.

In the table browser, click a cell to edit its full value in the inspector. Use **Set SQL NULL** for a database NULL; clearing the text leaves an empty string. Select a row number to open the popup and choose **Remove row** beside **Copy row as CSV** to mark it for deletion while leaving it visible. After dragging a range, the popup opens for the selection with **Remove selected rows**, which is also available above the grid. Right-clicking outside the selection targets only that row. **Save changes** applies all edits and removals together; **Undo** discards all staged changes. Save or undo before refreshing, changing tables, running SQL, switching connections, or disconnecting. Only real tables with a primary key support editing/removal; generated columns are read-only. Saves check the original row values and roll back the entire batch if a row changed, a constraint fails, or the operation is cancelled.

SQL results support the same staged cell edits and removals for a simple **SELECT from one table** that returns its primary-key columns, including composite keys. You can select a subset of columns, reorder them, or use column aliases; edits and removals use the source column names. Joins, aggregates, expressions, views, and results without the complete primary key remain read-only, with the reason shown in the row popup. Save checks the returned values and applies edits and removals in one transaction. Only returned columns participate in the conflict check; changes to omitted columns are preserved. Saved edits update the loaded result and removed rows disappear without running the SQL again, even if you have changed the editor text. Run the query again to refresh database-generated or trigger-modified values. Local result sorting keeps staged changes attached to the same rows.

The Fields form offers PostgreSQL TLS modes; its default is `prefer`, matching pgx. For certificate paths and other advanced options, use URL mode. URL TLS options are passed directly to pgx, for example `?sslmode=verify-full&sslrootcert=/absolute/path/root.crt`. Use `sslmode=disable` only when appropriate for a local test database. Saved URLs must include an explicit `sslmode` (or `ssl=true`) so their TLS mode cannot silently change with environment defaults; temporary URL connections still accept pgx defaults. Executed-query history is not yet persisted. Wails logging is restricted to warning/error level to avoid logging binding arguments containing credentials.

Multiple connections can be saved, but Tusk uses one active database session at a time. Switching providers reloads schemas and clears the previous results; SQL text stays in every query tab. Saved entries keep their own credentials and color tags. Saved providers are explicit: `postgres` or `sqlite`. Development entries with an empty provider must be deleted and recreated.

Drag the dividers to resize the sidebar, saved-connections/table-tree split, SQL editor/results split, and cell inspector. Focus a divider and use the arrow keys (Shift for larger steps), Home, or End to resize with the keyboard. Sizes remain while switching views and connections in the same window; relaunching resets the layout.

Open SQL tab drafts are stored as plain text in the macOS webview’s persistent local storage (`tusk.query-tabs.v1`). SQL results, editor undo history, and staged database changes last for the current window. A storage error stays visible so you can keep a copy of your SQL before quitting.

## Saved connection storage

Named connections are stored in `~/Library/Application Support/Tusk/connections.sqlite3`. The directory is private to your macOS account (`0700`), and the database file uses `0600`. Names, color tags, and connection summaries (provider, host, port, database, username, TLS mode, or SQLite file path) are stored as ordinary SQLite fields.

The complete credential payload, including URLs and passwords, is encrypted with AES-256-GCM before it is written to SQLite. Each record has a random nonce; authenticated metadata prevents a changed name, color tag, or endpoint from being used with an unchanged encrypted payload. The random encryption key is stored only in macOS Keychain, under service `io.tusk.app.connections`, account `encryption-key-v1`, with access limited to this device while its Keychain is unlocked. There is no file-based or plaintext fallback. Listing or deleting saved entries does not require decrypting them; connecting decrypts credentials inside Go without returning them through frontend bindings.

macOS may ask for Keychain access. Existing encrypted entries require their original key; if access is denied or the key is missing, Tusk reports an error instead of replacing the key. Backing up only the SQLite file does not preserve that key. URL passwords resolved from pgx environment/passfile defaults at save time are encrypted too; later password-default changes do not alter saved credentials. If a URL relies on host, port, username, or database defaults and those resolve differently later, reconnect fails with a request to save explicit settings.

In SQL results, column headings sort the displayed rows locally; sorting does not rerun the statement. Affected-row counts appear only for data-changing commands such as INSERT, UPDATE, and DELETE, including zero affected rows. SELECT results show returned/displayed rows and elapsed time.

Results preserve PostgreSQL text representations as strings across the Go–JavaScript bridge, including `bigint` and `numeric`. SQLite integers also retain their full precision; blobs display as hexadecimal SQL literals, and declared date/boolean columns retain their stored values. SQL NULL is represented separately from an empty string. Table previews are capped at 100 rows; SQL results are capped at 1,000 rows and approximately 5 MiB of cell data, with an explicit truncation indicator. These are display/bridge limits: excess rows are drained so writes with `RETURNING` can finish and commit. Database work remains cancelable and has a five-minute timeout; a single large database value can still consume backend memory while it is received.

## Checks

```sh
wails3 build                 # also generates bindings and builds frontend
cd frontend
npm run check
npm test
cd ..
go test ./...
go vet ./...
```

Integration checks require a **disposable** PostgreSQL database and create/drop their own randomly named schema. Set `TUSK_TEST_DATABASE_URL` and run:

```sh
TUSK_TEST_DATABASE_URL='postgres://user:password@127.0.0.1:5432/tusk_test?sslmode=disable' go test -race -v ./...
```

Without that variable, PostgreSQL integration tests explicitly skip. SQLite provider tests run with temporary database files and cover catalogs, attached/temporary objects, quoted identifiers, exact values, writes with `RETURNING`, display limits, single-statement validation, cancellation, and reuse after errors. Local storage tests use temporary SQLite files and synthetic encryption keys; they cover restart persistence, encrypted file contents, metadata/ciphertext tampering, key loss, permissions, concurrent operations, explicit providers, provider/path edits, schema upgrades, and shutdown. The optional native Keychain check creates and removes a uniquely named test item, without using the production key:

```sh
TUSK_TEST_KEYCHAIN=1 CGO_ENABLED=1 go test -race \
  -ldflags='-extldflags=-mmacosx-version-min=13.0' \
  -run '^TestSavedConnectionNativeKeychainSecurity$' -v ./...
```

The integration suite covers field-based and PostgreSQL/JDBC URL connections, exact credential handling, and the connect → browse → query → cancel workflow, quoted identifiers, NULL/empty values, precise numeric results, single-statement execution, and result limits. The optional special-credential authentication test also creates and drops a synthetic PostgreSQL role; it skips when the test account lacks `CREATEROLE`. No database fixtures or mock backend are used by the application.

### Browser workflow check

After `wails3 build` has produced the frontend assets, Wails can run the same Go service and bindings in a loopback-only test server:

```sh
CGO_ENABLED=1 CGO_CFLAGS='-mmacosx-version-min=13.0' \
  CGO_LDFLAGS='-mmacosx-version-min=13.0' MACOSX_DEPLOYMENT_TARGET=13.0 \
  go build -tags server,production -ldflags='-extldflags=-mmacosx-version-min=13.0' \
  -o /tmp/tusk-ui-check .
WAILS_SERVER_HOST=127.0.0.1 WAILS_SERVER_PORT=8794 /tmp/tusk-ui-check
# Open http://127.0.0.1:8794 and connect to a disposable PostgreSQL database.
# Stop the test server with Ctrl+C when finished.
```

This is a testing mode, not a separate backend for the desktop app.

## Current limits

Tusk uses one active database connection at a time. Table previews load the first 100 rows; query results are capped at 1,000 rows and approximately 5 MiB of cell data. Pagination, table filters, resizable columns, and executed-query history are not implemented. Open SQL tab drafts are persisted locally. Queries accept one statement per execution; explicit transaction workflows and multi-statement scripts are not supported. Only macOS packaging is currently configured.
